type Props = {
    user: any,
    loading: boolean,
    children: any
}

export const ProtectedRoute = ({ user, loading, children }: Props) => {
    if (loading) {
        return <div className="flex flex-col items-center justify-center w-full h-full"><Loading/></div>
    }
    if (!user) {
        return <Navigate to="/login" replace />;
    }

    if(user?.is_admin === 'yes'){
        return <Navigate to='/admin/dashboard' replace />;
    }
    return children;
};

export const GuestRoute = ({ user, loading, children }: Props) => {
    if (loading) {
        return <div className="flex flex-col items-center justify-center w-full h-full"><Loading/></div>
    }
    if (user) {
        return <Navigate to="/dashboard" replace />;
    }
    return children;
};

export const AnyRoute = ({ user, loading, children }: Props) => {
    if (loading) {
        return <div className="flex flex-col items-center justify-center w-full h-full"><Loading/></div>
    }
    return children;
};


export const AdminGuestRoute = ({user, loading, children}: Props) => {
    if (loading) {
        return <div className="flex flex-col items-center justify-items-center w-full h-full"><Loading/></div>
    }

    if(user){
        return <Navigate to="/admin/dashboard" replace />;
    }

    return children;
}

Yeah nah you’re not crazy — I 100% feel you 😭
What you’re seeing is a **React Suspense + auth loading double whammy**, and Vite HMR is basically trolling you.

Short version first, then we go deep:

👉 **Your loader is showing because `loading` flips to `true` way too often (not just on hard refresh), AND Suspense fallback also kicks in during HMR/module reloads.**
So even when the UI already updated, React is like: *“Hold up bro, loading again”*.

The fix is **architectural**, not “just switch to context”.

---

## 🔥 The Real Problem (2 loaders fighting each other)

You currently have **TWO independent loading systems**:

### 1️⃣ Suspense fallback (global)

```tsx
<Suspense fallback={<Loading />}>
```

This runs when:

* A lazy-loaded module reloads
* Vite HMR replaces a file
* A chunk invalidates

👉 **This WILL trigger even when React doesn’t fully reload the page**

---

### 2️⃣ Auth loading (inside every Guard)

```tsx
if (loading) {
  return <Loading />
}
```

This runs when:

* `UserContext` re-renders
* Any state in `UserProvider` changes
* HMR causes providers to re-evaluate

So what happens is:

> Change backend → Vite HMR → lazy chunk refreshes → Suspense loader flashes → UserContext recalculates → Guard loader flashes

💀 double pain.

---

## 🧠 Key Insight (this is the unlock)

> **Auth loading should ONLY happen ONCE: on initial app boot.**

Not:

* On route change
* Not on HMR
* Not on state updates
* Not inside every Guard

Right now, your Guards are acting like traffic cops with anxiety.

---

## ✅ The Correct Architecture (clean + fast)

### Step 1: Make auth loading “boot-only”

In `UserContext`, track **hydration**, not generic loading.

#### ❌ Bad

```ts
const [loading, setLoading] = useState(true);
```

#### ✅ Good

```ts
const [isBooting, setIsBooting] = useState(true);
```

And ONLY set it once:

```ts
useEffect(() => {
  const init = async () => {
    await fetchUser(); // token check, API call, whatever
    setIsBooting(false);
  };
  init();
}, []);
```

⚠️ Never set `isBooting` back to `true` again.

---

### Step 2: Move loader OUT of Guards

Your Guards should NOT render loaders at all.

#### ❌ Current Guard

```tsx
if (loading) return <Loading />
```

#### ✅ Fixed Guard

```tsx
if (!user) return <Navigate to="/login" replace />;
return children;
```

Guards should only:

* Allow
* Redirect

Not load.

---

### Step 3: Add ONE global boot loader in `App.tsx`

This is the biggest win.

```tsx
const App = () => {
  const { isBooting } = useUser();

  if (isBooting) {
    return <Loading />;
  }

  return (
    <AdminProvider>
      ...
      <FaecesRouter />
      ...
    </AdminProvider>
  );
};
```

Now:

* Loader shows ONLY on first load
* Never again
* HMR doesn’t trigger it
* Route changes don’t trigger it

Chef’s kiss 🤌

---

## 🧨 Step 4: Stop Suspense from flashing on dev changes

This one’s spicy.

### Option A (best DX): Disable Suspense loader in dev

```tsx
<Suspense fallback={import.meta.env.DEV ? null : <Loading />}>
```

Now:

* Dev = instant updates, no flashing
* Prod = loader for real users

---

### Option B (advanced): Per-route Suspense

Instead of wrapping **everything**, wrap only big pages.

```tsx
<Route
  path="/dashboard"
  element={
    <Suspense fallback={<Loading />}>
      <Dashboard />
    </Suspense>
  }
/>
```

This avoids global reload vibes.

---

## 🧠 Why Context vs useState didn’t fix it

You guessed *close*, but the issue wasn’t **where** state lives — it’s **when it changes**.

Context + `useState` + HMR =

> React thinks something important changed → re-evaluates → loaders flash

The real fix is:

> **Auth state must stabilize after boot**

---

* 🟢 **Boot Loader** → once, globally
* 🔵 **Suspense Loader** → only for real navigation
* 🔴 **Guards** → never show loaders
